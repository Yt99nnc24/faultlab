# FaultLab

A working, software-only virtual troubleshooting workshop for learners and instructors. It runs with static HTML, CSS and JavaScript. No package installation, API key or physical equipment is required.

## Run

Run `python -m http.server 5032 --directory dist` from this directory, then open http://127.0.0.1:5032. Windows users can double-click `start.cmd` with Python installed.

Run `npm test` or `node check.cjs` with Node.js 20+ to execute the simulation tests. Serve `dist/` as the site root on any static hosting service; no build step is required.

## Working features

- Dashboard with real local session counts and outcomes; no invented student metrics.
- Five authored single-fault cases: closed supply, restricted hose, blocked inlet screen, open valve circuit, and level signal stuck high.
- Ten context, operation, water-path and component diagnostic actions.
- Interactive front, service and conceptual system-path illustrations, including keyboard-accessible hotspots.
- Actual WebGL 3D washer with orbit/zoom, PBR-style materials, studio environment reflections, rounded panels, chrome bezel, perforated drum, printed controls, rear frame, springs and motor details.
- 3D focus mode, auto-rotation, exploded view, shell transparency, optional labels and visual door animation after virtual supply isolation.
- Virtual power and water isolation gates, blocked-action logging, simulated time and credit budgets.
- Customer conversation with authored case-specific replies and supported free-text question matching.
- Practice/exam modes and standard/focused challenge budgets.
- Evidence ledger with IDs, observation provenance and post-repair labels.
- Hypothesis sliders, reload-safe notebook and diagnosis with at least two distinct cited checks.
- Virtual repairs, unnecessary-repair costs, post-repair verification and gated completion.
- Guided rule-based coaching, disabled during exam mode.
- Outcome report, explicit 100-point rubric, action replay, JSON download and browser print/save-PDF.
- Local progress history and instructor cohort table.
- Instructor assignment codes that export settings for another local browser session.
- Six-question knowledge check with explanations.
- Searchable field notes and manufacturer reference links.
- Optional browser speech input/read-aloud and partial Hindi navigation/key headings.
- Local backup, schema-checked restore and deletion controls.

## Architecture

`dist/engine.js` is a standalone, testable simulation engine. It controls the hidden fault, observation results, gates, credits, diagnosis, repairs, verification and assessment. `dist/app.js` owns the interface, local persistence, roleplay presentation, instructor configuration and exports. `dist/scene.js` builds an original procedural 3D model and owns the WebGL viewer; it does not decide diagnostic results. `dist/styles.css` defines the responsive workshop UI. `check.cjs` tests all five complete paths, negative paths, safety and budget gates, scoring and basic backup validation.

The 3D renderer loads Three.js 0.180.0 and its official addons from jsDelivr through an import map. Internet access and WebGL2 are required for 3D; the interactive 2D preview and diagnostic toolkit remain available when WebGL cannot initialise. It is not an offline-bundled 3D engine. The Three.js project is MIT licensed: https://github.com/mrdoob/three.js/blob/r180/LICENSE. No third-party 3D model assets or textures are embedded; the machine geometry and surface textures are generated by this application.

The engine is deterministic after initial case selection. Only the initial random fault selection is random. No language model controls machine state or evaluates unstructured reasoning. The reasoning field is recorded for human review; automatic scoring checks selected diagnosis and relevant evidence IDs, not semantic quality of the prose.

## Important limits

This is a generic, simplified training model, not an exact digital twin or a service procedure for any manufacturer's appliance. Training times and credits are invented educational values. There are no real electrical resistance specifications. Real equipment requires appropriate manufacturer information and qualified supervision.

Customer roleplay and coaching are rule-based. Generative AI is not connected. Voice recognition may send audio to the browser provider. It is only used after the learner chooses that option; typing remains available.

All learner data is kept in localStorage in the current browser. Instructor mode is not a separately authenticated account, and local exam mode is not secure invigilation. Scenario answers are present in client-side source. There is no remote classroom database, automatic multi-device sync, accredited certification, 3D physics engine, custom combined-fault authoring, or real-machine connection. The viewer is a detailed generic visual model; geometry, component positions and fluid appearance are not a physically validated machine simulation. Hindi support currently covers navigation and key headings; technical content remains English.

An assignment code shares settings only. A JSON backup or session report can include learner names and notes; handle it as private data. Changing the hosting domain creates a different browser-storage origin and will not move existing learner records automatically.
